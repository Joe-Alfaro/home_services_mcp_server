# Requirements: Home-Services Data Layer and MCP Server

Status: approved scope for the MVP build. Requirement IDs (R1-R29, G1-Gn) are stable: code, tests,
docs and commit messages refer to them. Design: [`ARCHITECTURE.md`](../../ARCHITECTURE.md).

## Goal

A home-services marketplace connects homeowners with local service providers (handymen, plumbers,
HVAC techs, cleaners and more). Those providers keep their job data in six differently shaped
sources. This project ingests every source through its own adapter, normalizes the data into one
canonical model of providers, homeowner properties, jobs (past and upcoming) and availability,
resolves duplicate providers and homes with a stated method and a confidence, tracks where every
record came from, and exposes the result through a read-only, privacy-aware MCP server. An AI agent
connected to that server must answer the six benchmark questions below correctly.

Judgment matters more than polish: a smaller system with sharp, explained reasoning beats a big one
with none.

## Conventions used by the done checks

- **Data pack:** the synthetic source data is never committed. Setup reads it from `DATA_PACK_DIR`
  (default `../_private/data_pack` relative to the repo root). It holds `sources/jobber/`,
  `sources/housecall_pro/`, `sources/workiz/`, `sources/spreadsheet/`, `sources/calendars/`,
  `sources/profiles/` and `reference/street_segments.csv`.
- **Commands** (defined in `package.json`): `npm run setup` (one command: start Postgres, migrate,
  ingest, ready to serve), `npm start` (MCP server on stdio), `npm test` (unit tests),
  `npm run test:integration` (Postgres tests on an isolated database), `npm run eval` (eval harness),
  `npm run check` (format, lint, type check, tests, scrub check).
- **"Today"** is `2026-11-02` and **"now"** is `2026-11-02T00:00` America/Chicago
  (`2026-11-02T06:00:00Z`, the CRM snapshot time). Both are configurable (`HS_TODAY`, `HS_NOW`);
  the system clock is never used.
- **Relative windows** (local America/Chicago dates, start inclusive, end exclusive):
  - "last 24 months" = `[2024-11-02, 2026-11-02)`
  - "next 3 days" = `[2026-11-02 00:00, 2026-11-05 00:00)`
  - "next 14 days" = `[2026-11-02 00:00, 2026-11-16 00:00)`
  - "this week" = Monday to Sunday containing today = `[2026-11-02 00:00, 2026-11-09 00:00)`
- **Fixtures:** tests use small hand-made fixtures under `test/fixtures/` that mimic each source's
  shape with invented names and addresses. No rows from the data pack appear in the repo.

## Requirements

Priority: **must** = required; **should** = expected; **bonus** = the one chosen stretch goal.
Every done check is pass/fail and runnable by someone who has not seen the implementation.

### Fixed decisions reflected above

- Times: instants in storage, America/Chicago in presentation, zone-less inputs are Chicago local
  with DST (R12). "Today" 2026-11-02, configurable (R14).
- Privacy: hundred-block plus zip; full address only when the caller supplied it (R17).
- Availability: conservative merge with confidence and reasons (R13).
- Server: read-only, stdio, enforced by a read-only database role (R15, R16).
- Setup: runs locally with one command; there is no deploy and no public URL (R22).

## Benchmark questions

Today is 2026-11-02. These are verbatim.

| Q   | Question                                                                                                                            | Main requirements                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| Q1  | What home services have been done within half a mile of 4512 Live Oak St, Dallas, TX 75204 in the last 24 months, grouped by trade? | R3, R5, R7, R9, R12, R14, R15, R17 |
| Q2  | Which handymen have done work in zip 75214 and have an opening of at least 2 hours in the next 3 days?                              | R6, R12, R13, R14, R15             |
| Q3  | What work is already scheduled on the 4500 block of Live Oak St in the next 14 days?                                                | R7, R9, R12, R14, R17              |
| Q4  | Show me everything we know about Lone Star Plumbing: trades, service area, job history, and next 3 openings.                        | R6, R11, R13, R19                  |
| Q5  | Has any provider serviced 5823 Belmont Ave, Dallas, TX 75206 before? Who, when, and what was done?                                  | R7, R9, R17, R19                   |
| Q6  | Which plumber near 75206 is the best fit for a water heater replacement this week, and why?                                         | R13, R21, R4 (free-text job types) |

Interpretation used by the eval harness:

- **Q1:** "done" = canonical status `completed`, end time in the last-24-months window. "Within half
  a mile" = great-circle distance ≤ 804.7 m between interpolated coordinates. Grouped by canonical
  trade with counts; estimates and cancelled jobs excluded; CRM A visits of one job count once.
- **Q2:** "handymen" = providers whose canonical trades include `handyman`; "done work in 75214" =
  at least one completed job at a 75214 property; "opening" = a contiguous R13 opening ≥ 120 minutes
  in the next-3-days window. Each provider is listed with its openings and their confidence.
- **Q3:** house numbers 4500-4599 on Live Oak St; status `scheduled` or `in_progress`; start in the
  next-14-days window; estimates included but labeled; shown at block level only.
- **Q4:** resolves the name to one canonical provider (or explains the candidates if ambiguous) and
  returns trades, declared and observed service area, job history summary, the next 3 openings with
  confidence, profile-vs-observed conflicts and sources.
- **Q5:** matches the home through address normalization (R7); returns each provider, date and
  service; homeowner identity is never shown.
- **Q6:** no single right answer; correct = a complete, explained, sourced ranking (R21).

## Out of scope

- Booking, payments and messaging.
- Any user interface; an agent chat is the interface.
- Live calls to real CRM APIs or outside geocoders.
- Deploys, hosted environments, public URLs and remote repositories.
- Writing back to any source.
- Week-2 ideas (recorded in `docs/decisions.md`, not built):
  - **R30** New source in under an hour: absorb a seventh source using the adapter contract.
  - **R31** Incremental sync: re-ingest one changed source without a full rebuild, including a job
    that moved from upcoming to completed.
  - **R32** Access tiers: internal vs partner detail levels enforced by the server, not the agent.
